What Is an LLM Agent?

An LLM agent runs an LLM in a loop: the LLM picks a tool, our code runs it, the result goes back to the LLM, and the loop repeats until it can answer (Yao et al. 2023).

The LLM never runs code itself. It writes a structured request, and our code runs it (Schick et al. 2023).

Messages, Tool Calls, and Results

messages = [{"role": "user", "content": QUESTION}]   # conversation so far
turn = {"tool": "get_prices",                        # the LLM's request
        "args": {"ticker": "HSKY", "start": "2026-01-02",
                 "end": "2026-06-30"}}
result = TOOLS[turn["tool"]](**turn["args"])         # our code runs it

  • Message history: everything said so far, which the LLM reads each turn
  • Tool arguments: the inputs the LLM chooses for a function
  • Result: what the function returns; we append it to the messages

The Whole Agent Loop

def run_agent(question, llm, tools=TOOLS, max_steps=8):
    messages = [{"role": "user", "content": question}]
    trace = []
    for _ in range(max_steps):
        turn = llm(messages)                      # model picks next action
        if "final" in turn:
            trace.append(turn)
            return trace
        try:
            result = tools[turn["tool"]](**turn["args"])   # we run the tool
        except Exception as e:
            result = {"error": str(e)}
        trace.append({**turn, "result": result})
        messages += [{"role": "assistant", "content": turn},
                     {"role": "tool", "content": result}]  # model sees it
    trace.append({"stopped": f"hit max_steps={max_steps}"})
    return trace

Line 5 asks the LLM; 6 to 8 stop on an answer; 9 to 12 run the tool; 13 to 15 feed the result back; 16 is the step cap.

Other Ways Agents Fail

  • Bad arguments: tools should return errors that say how to recover
try:
    get_prices("HSKY", "2026-01-03", "2026-01-04")   # a weekend
except ValueError as e:
    print(e)
no trading days from 2026-01-03 to 2026-01-04; data covers weekdays 2026-01-02 to 2026-06-30, so try a wider window
  • Tool cost: a step cap limits LLM calls, not how long one tool call runs, so tools need their own limits
  • Untrusted tool output: text in a file or web page can hijack the agent (prompt injection) (Greshake et al. 2023)
  • Overkill: a fixed pipeline may be enough (Schluntz and Zhang 2024)

Evaluating an Agent

  • Success criterion: a task passes if the final answer names the correct winner and a gap within 0.01 points of the pandas value
  • Task selection: write a pool of questions (tickers, windows) before testing, then draw tasks from it at random
  • Model: each of n tasks is an independent Bernoulli trial with a common success probability p, so passes k ~ Binomial(n, p)
  • Estimate: p̂ = k/n with a 95% Wilson interval (Wilson 1927; NIST/SEMATECH 2012)

Hypothetical example: 17 of 20 passes gives p̂ = 0.85 with interval 0.640 to 0.948.

Takeaways

  1. An agent is an LLM in a loop with tools: the LLM chooses steps, and your code does the work.
  2. Put facts and arithmetic in tools, give them clear errors and limits, and keep the trace so every number is checkable.
  3. Judge an agent with a defined success criterion and an interval, not one demo.
