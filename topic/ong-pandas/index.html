Data Manipulation with pandas

Which majors pay the most? Four verbs answer it

Enrico Ong

Four verbs turn a table into an answer

Verb Question it answers pandas tool
Select Which columns do I need? .loc[:, cols]
Filter Which rows do I want? .loc[condition]
Create What can I compute from what I have? df["new"] = ...
Group What does each category look like? .groupby().mean()

Our question: which college majors pay the most? It is answered with these four verbs and no loops.

Tabular data is everywhere: spreadsheets, CSVs, records. Plain lists and loops can hold it, but every question needs hand-written code. pandas gives a DataFrame with labeled columns, so the same few verbs work on any dataset. Guiding question: how do a few operations take us from a raw table to an answered question?

Our data: earnings for 173 college majors

import pandas as pd

grads = pd.read_csv("data/recent-grads.csv")
grads[["Major", "Major_category", "Median"]].head(2)
Major Major_category Median
0 PETROLEUM ENGINEERING Engineering 110000
1 MINING AND MINERAL ENGINEERING Engineering 75000

Source: Casselman (2014), with data from the American Community Survey 2010 to 2012 (FiveThirtyEight 2014). Median is annual earnings in USD.

One row per college major, for recent graduates: number of graduates, share who are women, median earnings, unemployment rate, and how many hold jobs that need a college degree. One row has missing counts (Food Science). Full citation is on the Sources slide.

A DataFrame is two-dimensional. Each column has a name and a dtype. A single column pulled out is a Series. This deck is about manipulation, not import, so the import is one line.

Select: pick only the columns you need

grads.loc[:, ["Major", "Median", "Unemployment_rate"]].head(3)
Major Median Unemployment_rate
0 PETROLEUM ENGINEERING 110000 0.018381
1 MINING AND MINERAL ENGINEERING 75000 0.117241
2 METALLURGICAL ENGINEERING 73000 0.024096

Notice: three of 21 columns. : means “every row”.

  • Double brackets [[...]] return a DataFrame, single brackets a Series
  • Choosing columns first keeps later steps small and readable

.loc[rows, columns] selects by label. Narrow output keeps attention on what the question needs.

Filter: keep only the rows you want

is_eng = grads["Major_category"] == "Engineering"
engineering = grads.loc[is_eng]
len(engineering)
29

Notice: the condition gives True or False per row. Only True rows stay.

The Boolean Series goes into .loc[]. It is the pandas version of a WHERE clause in SQL. Both the comparison and the selection are vectorized, so no loop is written. 29 of the 173 majors are engineering.

Create: a new column from existing ones

grads = grads.copy()
grads["degree_job_share"] = grads["College_jobs"] / (
    grads["College_jobs"] + grads["Non_college_jobs"]
)
grads[["Major", "degree_job_share"]].round(2).head(2)
Major degree_job_share
0 PETROLEUM ENGINEERING 0.81
1 MINING AND MINERAL ENGINEERING 0.58

Notice: the share of grads in jobs that need a degree, computed for every major at once.

.copy() before assigning avoids a SettingWithCopyWarning when the table might be a view of another DataFrame. Counts are turned into a share so big and small majors can be compared.

Group: Engineering pays the most

by_category = (
    grads.groupby("Major_category")["Median"]
    .mean().round(0)
    .sort_values(ascending=False)
)

Notice: split by category, average each piece, combine into one result.

This is split-apply-combine. .groupby("Major_category") splits, ["Median"].mean() applies one summary per group, and the result comes back as a Series indexed by category. Engineering is about $57k, Business about $44k, Computers and Mathematics about $43k, and Psychology and Social Work lowest at about $30k.

Check how many rows each average used

(grads.groupby("Major_category")["Median"]
 .agg(majors="size", average="mean").round(0)
 .sort_values("majors").head(3))
majors average
Major_category
Interdisciplinary 1 35000.0
Communications & Journalism 4 34500.0
Law & Public Policy 5 42200.0

Notice: Interdisciplinary is one major, so its average is just that major’s median.

size counts the majors in each category. Small groups make shaky averages. Also, each major counts equally here, whether it has 400 or 400,000 graduates, because we averaged the major medians. One row (Food Science) is also missing its graduate counts, which mean() of Median is not affected by but would matter for a weighted average.

What the result does and does not say

Supports

  • Engineering leads: $57k on average, versus $40k for all majors
  • Range: Petroleum Engineering $110k, Library Science $22k
  • Pay and unemployment are weakly related (correlation -0.11)

Does not show

  • That the major causes the pay: who picks a major also matters
  • Pay today: data are from 2010 to 2012
  • Pay for one person: these are medians per major
  • Weighted results: each major counts equally, large or small

Best claim: engineering majors earn the most here. A pattern, not a cause.

This describes recent graduates in 2010 to 2012 survey data. A group average says nothing about why categories differ; who chooses a major, the local job market, and later career changes would need more data and a different analysis. The $40k figure is the mean of the 173 major medians (40,151). The correlation between median earnings and unemployment rate across majors is -0.11, which is weak. To go further: weight by Total graduates, check Sample_size, and use newer ACS data.

Four mistakes to avoid

Mistake Fix
Chained indexing: df[df.x > 0]["y"] = 1 Use .loc[] once
Assigning after filtering, no .copy() Call .copy() first
"Engineering" vs "engineering " Clean text before comparing
groupby drops missing keys Pass dropna=False

Fastest habit: print .shape and .head() after every step.

Chained indexing can silently fail to modify the original table. String comparison with == does not fix capitalization or stray whitespace.

When pandas is the wrong tool

If your data… Consider
Does not fit in memory A database or chunked tool
Is pure numeric arrays NumPy
Needs joins across many large tables A database (SQL)
Has unclear columns Understanding it first

pandas shines on a table that fits in memory and has clear columns. Here: 173 rows and 21 columns.

A correct average is still only as meaningful as the definitions and data collection behind it.

Takeaways

  1. Four verbs (select, filter, create, group) cover most table work
  2. Filtering and grouping replace hand-written loops
  3. Check the output: how many rows did each summary really use?
  4. Claim only what the data show: a pattern is not a cause

Return to the guiding question: engineering majors lead in these data, and a few composable verbs showed it. Always re-read the output.
